# 🚗 Deep Learning Autonomous RC Car Project

## 📌 Project Overview

カメラ映像のみを用いたエンドツーエンド（End-to-End）自律走行RCカーの開発

- **実施期間**: 2023年3月〜2023年6月（大学4年次前期）
- **チーム構成**: 4名（うち1名が途中で離脱したため、3名で役割を分担し直して開発）
- **担当役割**
  - 学習データ収集コードの実装（`Collection.py`、前処理を含む）
  - 自律走行コードの実装・調整（`Driving.py`）
  - 走行不良の原因調査と、カメラ角度変更の提案
- **成果**
  - 練習用トラックを完走
  - モデルの決定係数（R²）: 66% → 82.15%（チームでのデータ追加収集・ハイパーパラメータ調整による）
  - 学習データ: 約43,000枚（学習 34,765枚／検証 8,692枚）

> Note: 詳細な実験データと分析結果は、添付の `Report.pdf`（韓国語）をご参照ください。

## 🛠 Tech Stack

- **Hardware**: Raspberry Pi, カメラ, RCカーシャーシ
- **Software**: Python, OpenCV, TensorFlow/Keras
- **Model**: NVIDIA DAVE-2 をベースとしたCNN（モデル構造・ハイパーパラメータは指導教員提供のコードを使用）

## 📂 Source Code

### 1. データ収集と前処理（`Collection.py`）［担当］

キーボードでRCカーを手動走行させ、カメラ画像と操舵ラベル（左・直進・右）を保存。
以下の前処理を実装。

- 画像の下半分（路面）を切り出し
- YUV色空間に変換
- 200×66にリサイズ
- カメラが左側を多く映すため、左端約10%を切り出し（モデル入力は66×180）
- ガウシアンぼかし
- 二値化（しきい値160）

### 2. モデル学習（`making_model.ipynb`）

指導教員提供のコードをベースに学習。CNNで特徴を抽出し、全結合層で操舵角を回帰予測。
平均二乗誤差（MSE）と決定係数（R²）で評価。

### 3. 自律走行制御（`Driving.py`）［担当］

学習済みモデル（`lane_navigation_final.h5`）を読み込み、推論した操舵角を左・直進・右の3段階に分けてモーターを制御。

カメラの取り付け位置を変更した際に基板の前後が反転したため、データ収集・走行コードのモーター駆動方向を修正。

### 4. 人検知による停止機能（`stop_when_detec_person.py`）※未搭載

人を検知すると停止する機能のプロトタイプ（OpenCV DNN + 学習済み物体検出モデル、スレッド処理）。
Raspberry Piの処理能力では走行に遅延が出たため、走行の安定性を優先して搭載を見送った。

## 💡 Trouble Shooting

### 課題: 特定のカーブで必ずコースを外れる

チームでは当初、車体の故障を疑っていたが、「特定の場所でだけ起きる」点から、データ側に原因があると考えた。

### 原因調査

撮影した走行画像約2,000枚を1枚ずつ目視で確認。
天井の蛍光灯の光が床に反射し、二値化後の画像に線のように写り込み、それを車線と誤認識していることを特定。

### 対応

カメラを下向きにして反射光が映り込まないようにする案をチームに提案し、採用された。
その後チームでデータを集め直し、練習用トラックを完走できるようになった。

## 💭 Retrospective

1. **環境変化への汎化**
   練習用トラックでは安定して走行したが、本番の直角で幅の広いコースでは精度が大きく下がった。そうしたコースの学習データを集めていなかったことが原因。今であれば、走行環境を想定したデータ収集の計画と、明るさ変更・ノイズ付加などのデータ拡張で汎化性能を高める。

2. **エッジでの推論**
   処理能力の不足で人検知機能は見送ったが、TensorFlow Liteによるモデルの軽量化・量子化を使えば、Raspberry Pi上でも両立できた可能性がある。

3. **データの質**
   カメラ角度の調整という物理的な対応でデータの質が改善された経験から、モデルを複雑にする前にデータを確かめることの大切さを学んだ。
