# 🚗 Deep Learning Autonomous Car Project (DeepRacer Prototype)

## 📌 Project Overview

**カメラ映像のみを用いたエンドツーエンド(End-to-End)自律走行車の開発**

- **実施期間:** 2023年 10月 ~ 2023年 12月 (大学3年次)
- **チーム構成:** 3名 (Core Members)
  - ※ 添付PDFには登録メンバー4名が記載されていますが、実質的な開発・実装は主要メンバー3名で遂行しました。
- **担当役割:**
  - **データ収集・前処理パイプラインの設計と実装 (担当)**: `Collection.py`における画像処理ロジックの実装
  - **ハードウェア課題の特定と解決策の立案 (提案・主導)**: データ分析に基づくカメラアングル調整のアイデア提示
  - 走行制御アルゴリズムの実装 (`Driving.py`)
- **成果:**
  - 練習用トラックにおける完走率 **100% 達成** (初期0%からの改善)
  - モデル決定係数(R-squared): 66% → **82.15%** へ向上

> **Note:** 詳細な実験データと分析結果については、添付の`Report.pdf`(韓国語)をご参照ください。本ドキュメントではその要点を技術的な視点で要約します。

## 🛠 Tech Stack & Architecture

- **Hardware:** Raspberry Pi, Wide-angle Camera, RC Car Chassis
- **Software:** Python, OpenCV, TensorFlow/Keras
- **Model Architecture:** * **Base Model:** **NVIDIA DAVE-2** (End-to-End Learning for Self-Driving Cars) アーキテクチャを採用
  - **Optimization:** 提供されたベースモデルに対し、本プロジェクトの環境（屋内トラック、ラズパイの計算資源）に合わせて入力層のサイズ調整やハイパーパラメータのチューニングを実施

## 📂 Key Source Code Description

### 1. データ収集と前処理 (`Collection.py`) - **[担当: 実装]**

学習データの質を担保するため、以下の前処理パイプラインを**自ら設計・実装**。

- **YUV色空間変換:** RGBと比較して照度変化に強いYUV形式を採用し、環境光の影響を軽減。
- **ROI (Region of Interest) Crop:** `image[:,int(w*0.1):]` により、車線認識に不要な背景ノイズをカット。
- **Resize:** モデル入力に合わせて `200x66` にリサイズし、計算負荷を最適化。

### 2. モデル学習 (`making_model.ipynb`)

- **アーキテクチャ:** 畳み込み層(CNN)で特徴抽出を行い、全結合層(FCN)で操舵角(Steering Angle)を回帰予測。
- **評価指標:** 平均二乗誤差(MSE)と決定係数(R-squared)を用いてモデルの適合度を定量的に評価。

### 3. 自律走行制御 (`Driving.py`) - **[担当: 実装]**

- 学習済みモデル(`lane_navigation_final.h5`)をロードし、推論結果に基づいてPWM制御信号を生成。
- **Exception Handling:** カメラエラーや通信断絶に備えた例外処理を実装。

### 4. (Unreleased) 物体認識機能 (`stop_when_detec_person.py`)

- **概要:** 人や障害物を検知して緊急停止する機能のプロトタイプ。
- **実装判断:** スレッディング処理を含めて実装したが、Raspberry Piのエッジコンピューティングリソース(演算能力)の限界により、走行レイテンシが発生。**「走行の安全性・リアルタイム性」を最優先するエンジニアリング判断**により、最終製品への搭載は見送った。

## 💡 Trouble Shooting & Engineering Decisions

プロジェクトで直面した最大の課題は、**「屋内照明の反射による白飛び（ホワイトアウト）」**であった。

### 課題: 特定区間での脱線

- トラックの特定コーナーにて、床面の光反射によりカメラが車線を認識できず（画像データ上で情報が欠落）、脱線が多発した。

### アプローチ1: ソフトウェアによる解決（限界） - **[担当: 検証]**

- **HSV変換・ヒストグラム平坦化:** 画像処理による補正を試みたが、白飛びした領域（画素値255）は情報自体が消失しているため、復元には限界があった。

### アプローチ2: ハードウェアによる解決（採用） - **[担当: アイデア提案・主導]**

- **物理的なアングル調整の提案:** ソフトウェアでの解決が困難であるとデータから判断し、**「カメラアングルを下向きに変更し、物理的に光を遮断する」という解決策を考案し、チームに提案**。
- **効果:** 乱反射の入射経路を物理的に遮断しつつ、車線認識に必要な画角(ROI)を確保することに成功。
- **結果:** 決定係数(R-squared)が **66%から82.15%へ劇的に向上** し、安定した自律走行を実現。

## 💭 Project Retrospective (2025年時点の振り返り)

本プロジェクトは大学3年次に実施したものだが、現在のエンジニアとしての視点で振り返ると、以下の学びと改善点が挙げられる。

**1. Sim2Real (シミュレーションと現実のギャップ) への理解** 当時、練習トラックでは完璧に走行できたが、照明条件が異なる環境では精度が低下した。これはAIモデルが特定の環境に**過学習(Overfitting)**していたためである。 現在であれば、学習データに対して明るさ変更・ノイズ付加・回転などの \**Data Augmentation（データ拡張）\** を積極的に適用し、モデルの**汎化性能(Generalization)**を高めるアプローチを取る。

**2. エッジAIの最適化技術** 当時はリソース不足で物体認識を断念したが、現在は **TensorRT** や **TensorFlow Lite** といったモデル軽量化・量子化(Quantization)技術が一般的である。これらの技術を用いれば、精度を維持しつつ推論速度を向上させ、Raspberry Pi上でもマルチタスク処理が可能であったと考える。

**3. データ中心のAI開発 (Data-Centric AI)** モデルの構造を複雑にするよりも、「カメラの角度調整」という物理的なアプローチでデータの質（Data Quality）を改善したことが、結果的に最大の性能向上につながった。この経験から、**「良質なデータこそがAI性能の鍵である」**という原則を深く学んだ。
